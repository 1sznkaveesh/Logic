Overview

The program stores a propositional formula as a rooted parse tree and runs the five required algorithmic tasks. It accepts the assignment's operator symbols: ~ for NOT, + for OR, * for AND, and > for implication.

Task 1 · Infix → prefixValidates the input and emits prefix notation.
Task 2 · Prefix → treeReconstructs the tree from the prefix tokens.
Task 3 · TraversalsIn-order, pre-order, and post-order, both recursive and iterative.
Task 4 · HeightRecursive height and breadth-first iterative height.
Task 5 · EvaluationEvaluates the formula for each assignment and prints its truth table.
Task 6 · DocumentationThis HTML analysis page plus Doxygen comments and configuration.

Implementation decisions

Input and tokenization

The assignment guarantees a well-formed, fully parenthesized infix formula, so a full general-purpose parser is not needed. The input is split into tokens: an atom may be a multi-character name (a letter or underscore followed by letters, digits or underscores), while ~ + * > and parentheses are one-character tokens. Spaces are ignored anywhere between tokens, and parentheses are checked, so an accidental extra bracket is reported as invalid input instead of becoming a false proposition in the tree.

Infix to prefix (Task 1)

The converter follows the Scanftree method, applied to tokens instead of single characters: reverse the token sequence, swap ( with ), produce a postfix sequence with a shunting-yard operator stack, then reverse that sequence to obtain the prefix expression. When every token is one character the prefix is printed compactly (>*PQ~R); if any atom name is longer, tokens are separated by spaces so that they stay readable. The prefix is stored as a token list, and Task 2 builds the tree from exactly that list, so compact single-letter prefixes like >*PQ~R cannot be misread as multi-letter names.

Tree convention

Binary operators have left and right children. A unary NOT node has its operand as its right child. In-order traversal adds parentheses around binary subformulas, preserving their structure.

Truth values

Atoms are assigned F or T. OR is Boolean disjunction; AND is Boolean conjunction; implication evaluates as (not P) or Q. The unique variables are collected once and assigned indexes so each leaf's truth lookup is constant-time during evaluation.

Algorithm and complexity analysis

Let m be the number of characters/tokens in the input formula, n the number of parse-tree nodes, h the tree height, v the number of distinct atoms, and w the maximum tree width.

Infix → prefixO(m)O(m)Tokenizes the input, then reverses, swaps parentheses and runs the shunting-yard step over token arrays.
Prefix → treeO(m)O(n)Each prefix token creates one tree node.
Recursive traversalsO(n)O(h) call stackEach node is visited once.

Iterative post-orderO(n)O(n)Uses two stacks.
Recursive heightO(n)O(h)Returns −1 for an empty tree and 0 for a leaf.
Iterative height (BFS)O(n)O(w), up to O(n)Processes the tree one level at a time.
Collect variable namesO(n·v) worst caseO(v)Linear search over the atom names collected so far; negligible for the formula sizes used in Part A.
Evaluate one assignmentO(n)O(h)Evaluates child formulas before their parent operator.
Complete truth tableO(2v · n)O(v + h)Exponential in the number of atoms; output size is also exponential.
DIMACS import/tree constructionO(L + C)O(L + C)L literal occurrences, C clauses; builds balanced OR/AND subtrees.
Interpretation. The standard tree algorithms are linear in the number of nodes. Truth-table generation is the exception: every one of the 2v assignments must be evaluated, so the number of rows becomes impractical for benchmark-sized formulas.

Using SAT Competition benchmarks

The project supports a separate --dimacs FILE mode. DIMACS CNF encodes clauses as integer literals: positive integers are atoms, negative integers are their negations, and zero ends a clause. The p cnf V C header gives the declared variable and clause counts, while full-line c comments are ignored.

A clause is built as an OR subtree; the formula is the AND of its clauses. The implementation combines each group into balanced binary trees, reducing the height of the generated representation compared with a fully left-associated chain.

./logic_assignment --dimacs examples/sample.cnf
Benchmark caution. The original SAT 2002 archive is large and is not bundled with this code. Try the included three-variable example first, then load a real benchmark file. For more than 16 occurring atoms, printing a complete truth table is deliberately skipped; attempting it would create at least 65,536 rows and quickly grow to millions or more.

Scope and limitations

  • Atom names consist of a letter or underscore followed by letters, digits, or underscores; spaces may appear between tokens but not inside a name. The input is expected to be fully parenthesized, as the assignment specifies; the converter also applies the usual precedence when parentheses around binary connectives are omitted.
  • The program constructs/inspects formulas; it is not a SAT solver and does not search for a satisfying assignment independently of truth-table enumeration.
  • Truth tables are printed only up to 16 distinct atoms to prevent unbounded exponential output.
  • DIMACS formulas are imported directly as CNF trees. A huge benchmark is not expanded into an infix string first, which avoids unnecessary memory use and avoids confusing DIMACS syntax with the assignment's symbolic infix syntax.
